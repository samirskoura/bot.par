2026.09.13-random-per-workflow-run

Complete package, including all runtime files and setup helpers.

- Adds credential-safe OAuth diagnostics to the revised 80-Creative engine.
- Token errors show only recognized OAuth codes and fixed guidance, not raw bodies.
- The same suitable headline may be used on many different Creatives.
- Personal headline files are the default, with no OpenAI key or product context required.
- 500/800-line UTF-8 files are supported; blank/comment/duplicate lines are ignored.
- Random selection from each Creative's unused suitable lines in THIS workflow run.
- All overnight checks share usage; no reset between checks.
- A new workflow run or re-run attempt resets only headline usage automatically.
- Current wording stays excluded; older headlines can be reused in the new run.
- Approved records, pending review waits, uncertain edits and target records persist.
- GitHub run ID plus attempt number defines the boundary; no new Secret is needed.
- Checkout loads the current branch to retain the latest review state on re-runs.
- Exhausted lists do not recycle within a run; the next workflow launch starts fresh.
- Repeat checks use each Creative's current wording and current-run usage.
- Invisible formatting and composed diacritics cannot disguise previously used wording.
- Rechecks authoritative per-Creative history before reserving each headline.
- Writes local state atomically, with a flushed temporary file.
- On Actions, encrypts, commits and pushes each reservation BEFORE the edit.
- A failed checkpoint stops the monitor with exit code 90 before that edit.
- Rechecks all live status/link protections AFTER the checkpoint.
- Retains reserved wording even when a status check skips an edit.
- An unconfirmed interrupted PATCH remains blocked rather than blindly retried.
- Similar but distinct personal lines are allowed; optional AI keeps its near-duplicate check.
- Existing per-Creative history, legacy last headlines and pending reservations are retained.
- Newly observed headlines are saved under their Creative IDs, including external edits.
- Account-wide history and historical hashes no longer restrict reuse across Creatives.
- The model prompt explicitly allows sharing wording across Creative IDs and batches.
- Malformed per-Creative history stops the run instead of silently clearing records.
- Token request fields and conditional Creative PATCH guards are retained.
- Adds safe recognized OpenAI error codes/types with no raw response logging.
- Allows at most three total attempts for temporary rate limits/server errors
  within a 180-second retry window, honoring valid Retry-After waits.
- Quota, billing, auth and unknown 429 responses stop without automatic retry.
- Exit code 78 saves encrypted history and stops the current monitor immediately.
- Scheduled jobs remain controlled by BOT_ENABLED; see OPENAI_429_HELP.txt.
- Workflow adds automatic recovery of a deleted state.json.enc from Git history.
- Supports replacing every file in the same repository while keeping Secrets.
- Restores only the latest saved encrypted state, never old code or an older fallback.
- Up to 80 unique eligible Creatives across 1-20 squads in ONE Ad Account.
- Manual default 80; scheduled fallback remains 30.
- OpenAI candidate batches of at most 30.
- Refreshes account Ads, linked Ads and the Creative before every edit.
- Requires all linked live Ads to be REJECTED and the Creative DISAPPROVED.
- APPROVED, PENDING, PENDING_REVIEW, unknown statuses and outside links block edits.
- Approval observations are retained in saved state.
- Every Creative PATCH tests DISAPPROVED status and the exact prior headline.
- Failed or incomplete responses stop processing; uncertain PATCH reservations remain.
- State schema is version 11; encrypted file format stays SNAP-STATE-AESGCM-1.
- Saved state is recovered using the existing encryption key and repository history.
- No per-Creative retry limit; only confirmed rejections can become eligible again.
- Encryption preflight happens before Snapchat access.
- Logs conceal target identifiers and headline details when PUBLIC_SAFE_LOGS=true.
